本站功能更新日志

这篇文章记录本站从建站以来的功能改动。
一方面给自己留个账，另一方面是留给之后接手继续开发的 AI：先看这篇了解「现在有什么、为什么这么设计」，再看本机的 MANUAL.md（日常操作）和 HANDOFF.md（背景、恢复步骤、待办）。
最新改动永远放在最上面。

最后更新：2026-11-16　当前版本：v2026.11.16

这篇文章怎么维护

1.1 更新步骤（固定四步）

  1. 改完站点、确认本地构建通过后，把本文开头的 date 改成当前时间，version 改成当天版本号。
  2. 把正文上方的「最后更新 / 当前版本」状态行同步改掉。
  3. 在下面的「更新记录」表格最上面插入一行（最新的在最前），四列按格式填。
  4. 如果功能清单有变化（新增/删除了某个能力），同步改「当前功能清单」那张表。

一次改动一行，别把几件事塞进同一行。改坏了要回滚时，这一行就是线索。

1.2 版本号规则

情况 写法 例子
当天第一次更新 vYYYY.MM.DD v2026.11.16
同一天第二次及以后 后面加 -2、-3 v2026.11.16-2
跨天 直接用新日期，序号重新从无开始 v2026.11.17

版本号跟着日期走，不跟功能大小走。这样不用纠结「这算 1.1 还是 1.2」，也方便和发布记录对上。

1.3 更新记录表格格式

固定四列，顺序不能变：

列 填什么 注意
日期 YYYY-MM-DD 与版本号里的日期一致
类型 只能从下面六个词里选一个 方便以后筛选、统计
改了什么 一句话：改了什么 + 用户能感知到的变化 不要只写「优化代码」这种等于没说的话
涉及文件 反引号包住的关键文件路径，多个用 、 隔开 只写最关键的 1～3 个，不用列全

类型词表（只允许这六个）：

类型 用于
新增 新功能、新页面、新配置项
修复 修 bug、修错位、修兼容问题
调整 行为/样式/文案变了，但不算新功能也不算修 bug
删除 删功能、删文件、删示例内容
安全 隐私、加密、权限、凭据相关
文档 只改了说明文档，不影响线上表现

项目速览

2.1 技术栈

部分 用什么
静态站点框架 Hexo 7
主题 Butterfly 5（配置覆盖写在自己的主题配置文件里，不改 node_modules）
文章格式 Markdown + 开头 --- 信息段
写作台 本机 Node 服务 + 单页 HTML，浏览器打开即用
发布 提交到云端私有仓库 → GitHub Actions 自动构建 → 发布到公开站点
加密 hexo-blog-encrypt，仅「随记」板块可用

2.2 目录里哪些能改、哪些别动

位置 说明 能不能改
source/_posts/ 所有文章 随便加，已发布的文件名（网址）不能改
source/css/custom.css 自定义样式（手机端横幅等） 可以改，主题升级不会覆盖
_config.yml 站点主配置（网址、加密文案、搜索、排除项） 可以改
_config.butterfly.yml 主题配置（导航、配色、注入样式、评论） 可以改
scaffolds/ 新建文章的模板 可以改
scripts/search-filter.js 搜索索引隐私过滤 别动，动了会把加密文章漏进搜索
自动构建流程文件 云端发布用 别动，改错会导致发布失败
tools/ 写作台源码 可以改，但不会上传到线上
node_modules/、public/ 依赖和构建产物 不要手改，随时可重建

2.3 三个板块

板块 分类 说明
我的软件 我的软件 自己做的小工具，可填版本号、平台，模板带「下载」「更新日志」小节
推荐软件 推荐软件 推荐别人的软件，一篇静态文章，不追版本
随记 随记 唯一支持密码加密的板块，日常记录

板块决定分类，也决定顶部导航归到哪个栏目。只有「随记」能填密码，软件类文章填密码会被写作台拒绝。

当前功能清单

3.1 阅读体验

功能 状态 说明
响应式布局 有 桌面、平板、手机三种断点
手机端顶部横幅 有 整图完整显示，不再放大裁切；标题放在下方主题色带里
深色模式 有 跟随系统自动切换，右下角保留手动开关
图片懒加载 有 用浏览器原生能力，不引第三方脚本
本地搜索 有 顶部放大镜，索引为 /search.json，打开即可搜
文章目录 有 长文右侧自动生成
字号/字体 有 正文 15px、代码 13px；只用系统字体，不加载网络字体
禁止搜索引擎收录 有 robots.txt 全站 Disallow

3.2 写作台（本机）

功能 状态 说明
启动方式 有 双击批处理文件，浏览器自动打开本机页面
三个板块切换 有 自动套对应模板
英文地址（slug） 有 决定文章网址 /posts/<地址>/；留空自动生成日期型地址
图片上传 有 按文章分目录存放，避免同名覆盖
下载文件上传 有 存到统一下载目录，正文自动生成「下载」小节
密码加密 有 仅「随记」；不填密码时自动删掉模板里的占位密码
站点设置 有 站点标题、副标题、作者、横幅、头像、公告、主题主色，页面直接改
文章管理 有 右侧列表可打开原文、逐篇删除
删除文章 有 删本机 .md 和该文章的图片目录；云端在下一次上传时同步删除
本地试构建 已撤 合并进「上传到云端」，云端构建失败会回传日志和失败步骤
发布 有 单个「上传到云端」按钮，约 1 分钟
发布前检查 有 单文件超过 25 MB 拦下；信息段缺失、未登录会提示

3.3 发布链路

  • 写文章、保存都只动本机文件，不点「上传到云端」不会有任何内容离开电脑。
  • 本机不需要安装 git，也不用手动开网页操作。
  • 同步是双向的：本地删掉的文章，上传时会一并从云端删除，不会出现「本地删了线上还在」。
  • 云端仓库里的密钥、登录凭据、本机路径都不随项目文件走。

已知限制

  1. 加密只锁正文：标题、网址、日期、分类仍然公开，会出现在归档页、分类页和 RSS 里。目前只是从搜索索引里剔除，归档/分类里仍可见。
  2. 密码是明文存在文章文件里，随文章进云端私有仓库。别复用在别处用过的密码。
  3. 忘了密码自己也解不开，没有找回途径。
  4. 加密密钥派生迭代次数为 250000，低于当前 OWASP 建议值。改这个值会让已发布的加密文章解不开，要改必须连密码一起重新加密，属低优先级。
  5. 下载目录是平铺的，多篇文章传同名文件会互相覆盖，文件名要带版本号。
  6. 评论系统没开：它要求仓库公开，和「封闭自用」冲突。配置位留好了，想开再填。
  7. 自定义域名没启用，目前用平台默认地址；启用步骤写在 _config.yml 注释里。
  8. 单文件硬上限 25 MB（平台侧 100 MB），大文件应该走外部网盘或 Release 附件。

给接手 AI 的约定

如果你是被叫来继续开发这个站点的 AI，请先按这个顺序来：

  1. 读本机的 MANUAL.md（用户日常怎么用）和 HANDOFF.md（项目背景、换电脑恢复、待办）。
  2. 读本文的「当前功能清单」和「已知限制」，别把已有功能当缺失重做。
  3. 看「更新记录」最近几行，了解上一轮改了什么、可能影响到哪里。

硬性规则：

  • 不要改 已发布文章的文件名（等于改网址，旧链接会失效）。
  • 不要动 scripts/search-filter.js 和自动构建流程文件；它们分别关系到隐私过滤和能否发布成功。
  • 样式改动写进 source/css/custom.css，不要改 node_modules（重装依赖或升级主题会被覆盖）。
  • 写作台只监听 127.0.0.1，不要改成对外监听。
  • 发布统一走写作台的「上传到云端」，不要另建发布通道。
  • 发布前必须本地 hexo generate 通过；改完在手机视口（建议 390×844）和桌面视口各看一次。
  • 隐私红线：文章和附件会进入公开站点，任何人都能下载。不要往文章、截图、示例里放令牌、密码、账号、本机绝对路径、内网地址。
  • 不要删除 source/_posts/ 里的真实文章，除非用户明确要求。

下一步计划

  • 想推广时放开搜索引擎收录（删掉 robots.txt 里的禁止规则）。
  • 需要评论时再评估是否接受公开仓库。
  • 加密文章标题是否也隐藏，需要单独加一层处理。
  • 横幅图可以按季节/节日轮换，换图在「站点设置」里操作，不用改代码。
